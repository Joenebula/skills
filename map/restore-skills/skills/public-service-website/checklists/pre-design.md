# Checklist — Pre-Design

Run before starting design on a new page or component. Don't design until these are answered.

## User need
- [ ] What is the user trying to do here? (one sentence, in their words)
- [ ] Which user need / top task does this serve?
- [ ] Is there a user journey this fits into? (`templates/user-journey.md`)
- [ ] What's the success measure?

## Audience & context
- [ ] Who actually uses this — including low-confidence, older, disabled, low-bandwidth users?
- [ ] What device and connection is the realistic worst case? (design for it)
- [ ] Any second-language or low-literacy considerations?

## Content
- [ ] Is the real content available, or at least drafted? (not lorem ipsum)
- [ ] Does the content team know the reading-age and plain-English requirement?

## Structure
- [ ] Where does this sit in the IA / sitemap?
- [ ] What's the primary path to and from it?
- [ ] What's the heading structure (H1 and outline)?

## Constraints
- [ ] Performance budget known (page weight target)?
- [ ] No-JS requirement understood for any core journey here?
- [ ] Which design tokens already exist to reuse? (`templates/design-tokens-starter.md`)
- [ ] Which Bootstrap components are candidates, and any to avoid? (`references/bootstrap-foundation.md`)

## Accessibility up front
- [ ] Which WCAG 2.2 criteria are most at risk for this page/component?
- [ ] Any forms → plan error handling, labels, grouping now.
- [ ] Any dynamic content → plan focus management and announcements now.
- [ ] Any media/imagery → plan alt text and captions now.

## Compliance
- [ ] Is this a public sector body (PSBAR applies)?
- [ ] Any personal data collected (UK GDPR)?
- [ ] Campaign site (imprint needed)?
- [ ] Check the loaded project profile for project-specific decisions.
